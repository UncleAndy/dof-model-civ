# DOF-политика во встроенном ИИ freeciv — рабочий набор

Состояние: **M0, M1, M2, M3 и солидарность (M4) исполнены и проверены прогонами** (2026-10-25). Ниже — что именно лежит в контейнере `freeciv-web` и как это измерять.

Полное описание изменений в движке (по файлам, с кодом, замерами и границами изменения): `drafts/DOF_ENGINE_CHANGES.md`. Здесь только рабочий набор.

`orig/` (девственные копии правленых файлов) в репозиторий не кладётся: его всегда можно достать из контейнера —
`docker cp freeciv-web:/docker/freeciv/freeciv/<путь> deploy/freeciv-dof/orig/<имя>`; диффы в `patches/` сняты именно с них.

## Переключатель

Файл в контейнере `/docker/freeciv/dof_policy.conf` (или `DOF_POLICY_FILE`), одна строка:

```
none | all | even | odd | 0,2,4      # комментарий
```

`even`/`odd` выбирают места по индексу игрока — так **обе руки играют одну партию**: половина мест классическая, половина DOF. По умолчанию в контейнере стоит `none`, то есть живой стенд ведёт себя как раньше.

Плюс консоль `aicmd <player> dof on|off|status` — для точечной проверки на живом клиенте.

## Журнал (что писать в разбор)

Все строки — префикс `[DOF]` в серверном логе:

```
[DOF] policy=<spec> turn=N
[DOF] roster ai_seats=[Имя:idx=0:dof=1,...]
[DOF] contact turn=N me=X other=Y status=MET|SOURCE
[DOF] declare turn=N declarer=X target=Y declarer_dof=0|1 reason=N
[DOF] attack turn=N violator=X victim=Y violator_dof=0|1 victim_dof=0|1
[DOF] news turn=N violator=X victim=Y violator_dof=0|1
[DOF] rule turn=N me=X other=Y what=war_on_source|war_on_source_third|ceasefire_offer|coercion_refused
[DOF] desire_suppressed turn=N me=X other=Y n=1     (первое подавление пары)
[DOF] blocked turn=N me=X other=Y what=declare_war
[DOF] unit_source turn=N unit=ID utype=<тип> owner=X victim=Y
[DOF] unit_source_barb turn=N unit=ID utype=<тип> owner=X victim=Y   (варвар напал или варвар — жертва)
[DOF] unit_gone turn=N unit=ID owner=X victim=Y
[DOF] barb_summary turn=N marks=X rules=Y                            (раз в 50 ходов)
```

`declare`/`attack`/`news` пишутся **всегда**, обе руки — иначе «тихая» партия неотличима от «прибор не сработал». `unit_source` пишется на каждый учтённый удар и всегда с настоящим `unit=ID`; удары, где варваром является нападавший или жертва, идут отдельной меткой `unit_source_barb`, а пары с варваром в строках `rule`/`blocked`/`declare` получают поле `barb=1` — это только учёт, поведение не меняется; `unit_gone` закрывает пометку в тот ход, когда юнит уничтожен, — по этой паре видно, что войны заканчивались уничтожением юнитов, а не истечением срока.

## Что изменено на самом стенде (2026-10-25)

Файлы стенда вне движка, копии — в `stand/`:

* `/docker/scripts/install/dependency-services-default-start.sh` (её и есть симлинк `dependency-services-start.sh`) — MariaDB поднимается напрямую через `mariadbd-safe`: исходная строка `pidof mysqld || service mariadb start` в этом образе не работает (нет `service`, процесс называется `mariadbd`), плюс принудительный `chmod 1777 /tmp`. Без этого не стартовала база → прокси на 7002 падал в `check_user` (`cursor.close()` на None) и партии через клиент не шли вообще.
* `/docker/publite2/init-freeciv-web.sh` — `addArgs --debug 1` → `--debug 2` (иначе `log_normal` подавлен и строк `[DOF]` не видно).
* `/docker/freeciv/dof_policy.conf` — по умолчанию `even`: половина ИИ-мест ведёт себя по DOF. Переключение — одна строка, без рестарта.

**Журнал на стенде читать из stderr**, а не из `freeciv-web-log-<port>.log`: в этом окружении файл `--log` не обновляется (свежие — от 21.10), поэтому `dof_log` дублирует строки в stderr → `/docker/logs/freeciv-web-stderr-<port>.log`. Проверено живой партией через клиент:

```
[DOF] policy=even turn=1
[DOF] roster ai_seats=[Muhammad ibn Abdalla:idx=1:dof=0,Nicolás de Federmán:idx=2:dof=1,Amílcar Cabral:idx=3:dof=0]
```

## Как включить DOF на стенде (проверено)

Обновление кода в движке = `sh deploy/freeciv-dof/apply.sh` + `docker restart freeciv-web` (без рестарта живущие движки держат старый inode).
А включение политики рестарта **не требует**: файл читается в начале хода каждого ИИ-места, смена видна со следующего хода (проверено: файл переписан на ходу 5 — в журнале `policy=even turn=69` и новый состав мест; задержка — время генерации карты, а не кэш).

1. Выбрать руку — записать в `/docker/freeciv/dof_policy.conf`:
   * `all` — все ИИ-места ведут себя по DOF (войн не начинают вовсе);
   * `even`/`odd` — половина мест по DOF, половина классических (так идёт замер);
   * `0,2,4` — явный список индексов мест.
2. Поднять журнал: в `/docker/publite2/init-freeciv-web.sh` строка `addArgs --debug 1` → `--debug 2`, иначе строки `[DOF]` в `/docker/logs/freeciv-web-log-<port>.log` не пишутся (изменение требует рестарта контейнера).
3. Наблюдать: `docker exec freeciv-web grep "\[DOF\]" /docker/logs/freeciv-web-log-6001.log`.
4. Вернуть стенд в исходное: `none` в файле политики — со следующего хода все места снова классические.

Новая партия в том же процессе движка (`--keep`) чистит журнал источников и счётчики: ход пошёл назад — состояние обнуляется.

## Уровень логирования (важно)

Журнал идёт через `log_normal`, поэтому на **живом стенде** строки `[DOF]` не видны: publite2 запускает движки с `--debug 1`. Для наблюдения на стенде нужен `--debug 2` (или выше) в аргументах движка; безлюдные прогоны `run_ab.py` пишут лог по умолчанию, там журнал есть.

## Запуск серии

```bash
.venv/bin/python deploy/freeciv-dof/run_ab.py --games 4 --turns 120 \
    --aifill 8 --size 3 --par 4
```

Скрипт готовит `.serv` и файл политики внутри контейнера, поднимает безлюдные сервера на портах 61xx, ждёт выхода, забирает лог, вытаскивает журнал, пишет `logs/ab/series.jsonl` и печатает сводку.

## Замер 3: солидарность M4 (6 партий × 2 руки, 200 ходов, 8 мест, карта size 3)

Источник коллапса теперь определяется по любой известной паре «нападавший, жертва», а не только по паре «напал на меня»: место, которое знает и агрессора, и его жертву, вступает в войну на стороне жертвы. Журнал различает поводы: `war_on_source` (самозащита) и `war_on_source_third` (за третьего).

| рука | мест | объявлений | из них без повода | score | города | население | технологии | bulbs/ход |
|---|---|---|---|---|---|---|---|---|
| DOF-места смешанных партий | 24 | 12 | **0** | 175.8 | 19.8 | 63.5 | 40.8 | 155.9 |
| классические места тех же партий | 24 | 49 | 41 (84%) | 157.5 | 17.5 | 51.7 | 38.0 | 97.5 |
| контроль (`none`) | 48 | 138 | 130 (94%) | 172.1 | 18.4 | 58.5 | 40.8 | 144.2 |

Все 12 DOF-объявлений пришлись на того, кто до этого напал, и все 12 сопровождались строкой `war_on_source_third` — это войны за третьих лиц. Счётчики: `ceasefire_offer` 740, `coercion_refused` 248, `blocked` 1. Контрольная ветка не сдвинулась: `classic_sol` повторила прежнюю классическую серию точно (138 объявлений, 238.2 убитых юнитов, score 172.1, 40.8 технологии, 144.2 bulbs).

Цена солидарности: наука DOF-мест 177 → 156 bulbs при том же score (176.6 → 175.8), классические места в смешанных партиях 163.4 → 157.5. Войн у DOF-мест стало 12 за 24 места-партии против 3 за 48 в серии без солидарности.

## Замер 4: солидарность на уровне юнитов, M5 (6 партий × 2 руки, 200 ходов, 8 мест, карта size 3)

Источник коллапса теперь **юнит**, а не сторона. Пометка ставится конкретному `unit_id` и живёт, пока он жив: уничтожили юнит — источник исчез, место предлагает перемирие. Нападение стороны, по которой уже ударили раньше, ответом не считается источником: в паре запоминается, кто начал. Место с DOF ищет помеченные юниты первыми (`dai_rampage_want`, `desire *= 3`).

| рука | мест | объявлений | score | города | население | технологии | bulbs/ход | живых |
|---|---|---|---|---|---|---|---|---|
| DOF-места смешанных партий | 24 | 96 | **166.1** | 17.6 | 57.8 | 37.8 | 89.4 | 1.00 |
| классические места тех же партий | 24 | 52 | 156.5 | 16.6 | 49.4 | 38.1 | 78.1 | 0.96 |
| контроль (`none`) | 48 | 138 | 172.1 | 18.4 | 58.5 | 40.8 | 144.2 | 1.00 |

Счётчики за серию: `unit_source` 510 (все с настоящим `unit=ID`, записей `unit=0` нет), `unit_gone` 440, `war_on_source_third` 122, `war_on_source` 2, `ceasefire_offer` 1136, `coercion_refused` 142, `blocked` 15. Ветка «война ответа» срабатывала 124 раза, объявлений DOF-места сделали 96 (объявление идёт после `countdown`, не в тот же ход). Шесть партий из шести дошли до конца; в одной уничтожен один классический игрок — первый такой случай в замерах. Контроль `classic_unit2` повторил прежнюю классическую серию точно (138 объявлений, 238.2 убитых юнитов, 172.1 / 40.8 / 144.2).

Что видно: 440 из 510 пометок закрыто строкой `unit_gone`, то есть войны заканчивались уничтожением конкретных юнитов, а не истечением срока; каждое объявление DOF-места прошло предохранитель `dai_go_to_war()`, который пропускает только пару с живой пометкой и 15 попыток остановил.

Цена перехода на уровень юнита — резкий рост числа войн: 96 объявлений DOF-местами против 12 в серии M4 на том же числе мест-партий. Причина в полноте знания: раньше `call_incident()` сообщал только о нападениях с casus belli (первый удар, шпионаж, ядерный удар), теперь виден каждый бой (`unit_perform_action()`). В мире, где встроенный ИИ воюет постоянно, у кого-то всегда есть живой помеченный юнит, и место с DOF вступается почти непрерывно. По score оно это выдерживает (166.1 против 156.5 у классических мест тех же партий), но наука падает заметно: 89.4 против 144.2 у контроля.

## Первый замер (4 партии × 2 руки, 121 ход, 8 мест, карта size 3, только M0+M1)

| рука | мест | объявлений | из них без повода | атак |
|---|---|---|---|---|
| контроль (`none`), 4 игры | 32 классических | 36 | **33 (92%)** | 5 |
| DOF (`even`), DOF-места | 16 | 3 | **0** | 1 |
| DOF (`even`), классические места в тех же играх | 16 | 9 | 8 (89%) | 3 |

«Без повода» = цель объявления до этого хода ни на кого не нападала (по журналу `attack`).

Чтение: классическое место объявляет войну ради выгоды/неприязни в 92% случаев; DOF-место — только против того, кто уже напал (3 случая из 3: Сукарно против Теводроса, Рама Тибоди дважды против Суйко). Классические места в тех же партиях ведут себя как в контроле — смешение рук внутри партии на них не влияет.

## Живучесть пометки: правка после длинной серии (300 ходов)

Первая сборка уровня юнитов пересобирала срез пометок только после новой записи в журнал. Пометка юнита, погибшего между двумя инцидентами, оставалась в срезе живой до следующего инцидента: живучесть источника проверялась не в момент вопроса.

Правка: `dof_live_refresh()` пересобирает срез каждый ход, а `dof_is_source()` проверяет помеченные юниты через `game_unit_by_number()` прямо в момент вопроса.

Журнальная сверка идёт скриптом (по строкам журнала она различает не всё: `unit_gone` пишется тем же ленивым пересбором):

```
.venv/bin/python deploy/freeciv-dof/check_long.py long2_none long2_dof long2_even
```

После правки: `long2_dof` 650/650 объявлений с живой пометкой, `long2_even` 437/437, контрольный прогон 256/256. Серии `long_*` сняты на первой сборке и заменены сериями `long2_*`.

## Чего ещё нет

* Упаковка в собственный `aitype dof` (сейчас — флаг на место в классическом типе).
* Партии с живыми людьми не проверены: все серии безлюдные, все места — встроенный ИИ (внешних Python-агентов в проекте больше нет).
* Солидарность работает на уровне юнитов, но ответ — война против **стороны**, которой помеченный юнит принадлежит: freeciv не даёт воевать с юнитом, не объявив войну его владельцу. Отдельной «защиты жертвы» (перехват у её города, помощь ресурсами, ультиматум) нет.
* «Точно знает нападающего» ограничено знанием о нападении, а не зрением: место не обязано видеть, где стоит помеченный юнит, и потому в мире постоянных войн вступается почти непрерывно (96 объявлений за 24 места-партии, см. замер 4).
* Долгие партии (>120 ходов) и карты size 4–5: там войны классического ИИ идут позже, серия не покрыта.
* `blocked` (предохранитель в `dai_go_to_war`) в сериях почти не срабатывает: 0 в первых сериях и 1 раз в серии со солидарностью. Основная работа идёт на уровне желания войны, предохранитель остаётся страховкой; метрика «сколько раз укусило» считается через `desire_suppressed`.
