# Изменения в движке freeciv для принципа DOF-Core во встроенном агенте

**Статус:** DRAFT, описание исполненного (ненормативный канал, норматив живёт в `deploy/freeciv-dof/` и в патче образа). **Дата:** 2026-10-25. **Принцип:** [DOF-Core](https://github.com/UncleAndy/dof-core), математика и аксиомы в `DOF-SPEC.md` того репозитория; здесь только их перевод в код движка.

Где лежит код: рабочая копия `deploy/freeciv-dof/src/dofpolicy.{c,h}` (новый модуль) и `deploy/freeciv-dof/work/*` (правленые файлы движка), диффы `deploy/freeciv-dof/patches/*.patch`, собранный сводный патч для образа `AI/freeciv-web/freeciv/patches/dof-principle.patch` (10 файлов, 1013 строк).

## §1. Что именно изменено и чем это не является

Изменён **встроенный** агент freeciv, тот самый классический ИИ, который движок сам играет за ИИ-места (`ai/classic/classicai.c` поверх `ai/default/*`). Внешних агентов в проекте больше нет: партии играет только движок.

DOF здесь не второй ИИ и не отдельный `aitype`. Это **режим отдельного места**: у каждого игрока спрашивается `dof_enabled(pplayer)`, и если для места режим выключен, весь классический код работает так, как работал до правки. При политике `none` двоичный файл ведёт себя как исходный: это и есть контрольная рука любого замера.

Правило реализовано как набор **запретов и обязательств**, а не как мера свободы. Меры вида `Σ ln(1 + число допустимых действий)` в движке нет: движок не перебирает меню действий, чтобы оценить альтернативу по свободе. Что это означает для выводов, разобрано в §10.

## §2. Принцип DOF-Core, переведённый в термины движка

| формулировка принципа | что появилось в коде |
|---|---|
| Незнание не есть отсутствие возможностей, незнакомец не враг | `DS_NO_CONTACT` больше не даёт права считать игрока целью: макрос `POTENTIALLY_HOSTILE_PLAYER` для DOF-места не включает `NEVER_MET` (§4.6) |
| Коллапс начинается только с наблюдённого нападения | журнал источников `dof_source_until[нападавший][жертва]`, заполняемый в единственной серверной точке инцидентов `call_incident()` (§4.2, §3.4) |
| Мирное соседство увеличивает общую свободу, война за выгоду её уменьшает | `dai_war_desire()` возвращает 0 для DOF-места, если войны нет и нападения не было (§4.4а); блок «война за добычей» и «нет целей» такие пары пропускает (§4.4е) |
| Нападение должно быть отвечено, но только нападавшему | новый блок «война ответа» в `dai_diplomacy_actions()`: против источника война объявляется без расчёта выгоды и без учёта неприязни (§4.4ж) |
| Солидарность: кто видит нападающего и защищающегося, встаёт на защиту | источник определяется по любой известной паре «нападавший, жертва», а не только по паре «напал на меня»; война объявляется и за третьего, журнал различает `war_on_source` и `war_on_source_third` (§3.4, §4.4ж) |
| Война не должна становиться постоянным состоянием | после истечения флага источника DOF-место предлагает перемирие независимо от неприязни и без выкупа, снимая ветку `dai_goldequiv_clause` (§4.4к) |
| Принуждение есть нападение под другим именем | подкуп города, саботаж, кража технологии, яд, чума и ядерный удар шпионом против не-источника вне войны получают `utility = 0`; посольства и мирное присутствие остаются разрешены (§4.5) |
| Свобода одной стороны не покупается свободой другой | для DOF-места отключены «война за добычей» (§4.4е), «война ради остановки космогонки» (§4.4д), «война за союзника» (§4.4з) и «no mercy» (§4.4и) |

Флаг источника живёт `DOF_SOURCE_HORIZON = 20` ходов с момента нападения. По истечении война теряет предмет: место возвращается к мирному поведению и предлагает перемирие.

Внутренний инвариант замера: журнал пишет **обе руки всегда**. «Тихая» партия без строк `declare` неотличима от партии, где прибор не сработал, поэтому объявления и нападения журналируются независимо от флага места.

## §3. Новый модуль `ai/default/dofpolicy.{c,h}`

Модуль не знает ничего о правилах игры, он держит три вещи: политику (какие места играют по DOF), знание (кто на кого напал) и журнал.

### §3.1. API

| функция | назначение |
|---|---|
| `dof_policy_reload()` | перечитать файл политики, если он изменился; обнулить состояние при новой партии в том же процессе |
| `dof_enabled(pplayer)` | играет ли это место по DOF (учитывает консольное принуждение, затем режим файла) |
| `dof_is_source(pplayer, other)` | считается ли `other` источником коллапса с точки зрения `pplayer` (напал на меня или на известного мне) |
| `dof_source_is_third_party(pplayer, other)` | источник ли `other` из-за нападения на третьего, а не на меня: разделяет солидарность и самозащиту в журнале |
| `dof_journal_contact()` | первый контакт: незнакомец опознан как `MET` или `SOURCE` |
| `dof_journal_blocked()` | политика остановила действие, которое классическая рука выполнила бы |
| `dof_journal_rule()` | политика сработала по доктрине: война ответа, предложение мира, отказ от принуждения |
| `dof_count_suppressed()` | счётчик ходов, на которых желание воевать с данной парой было обнулено |
| `dof_journal_declare()` | объявление войны любым ИИ, с флагом руки объявившего |
| `dof_ledger_note()` | запись инцидента от сервера: нападение или объявление |
| `dof_player_console()` | консольная команда `/aicmd <player> dof on|off|status` |
| `dof_policy_spec()` | текущая строка политики для журнала |

### §3.2. Состояние

```c
static struct {
  bool loaded;
  time_t mtime;
  enum dof_mode mode;              /* NONE | ALL | EVEN | ODD | LIST */
  bool listed[MAX_NUM_PLAYERS];    /* режим LIST */
  char spec[DOF_SPEC_LEN];         /* как записано в файле */
  signed char force[MAX_NUM_PLAYERS]; /* консоль: 0 нет, 1 включено, 2 выключено */
} dof_policy;

static unsigned short dof_suppressed[MAX_NUM_PLAYERS][MAX_NUM_PLAYERS];
static int dof_source_until[MAX_NUM_PLAYERS][MAX_NUM_PLAYERS]; /* ход истечения */
```

Обе матрицы квадратные по числу игроков: движок ограничен `MAX_NUM_PLAYERS`, поэтому отдельной структуры знаний по игрокам не понадобилось.

### §3.3. Перечитывание политики

`dof_policy_reload()` вызывается часто, в том числе из плотных военных циклов через `POTENTIALLY_HOSTILE_PLAYER`, поэтому `stat()` делается не чаще одного раза за ход: проверка кэшируется по `game.info.turn`. Изменение файла видно со следующего хода, рестарт сервера не нужен.

Если номер хода пошёл назад (движок живёт с `--keep` и начал новую партию), журнал источников и счётчики обнуляются: иначе источники прошлой игры переехали бы в новую.

### §3.4. Журнал источников

Единственная точка записи знания это `call_incident()` сервера, откуда инцидент уходит в `dof_ledger_note()`. Нападением считаются 20 результатов действий (`ACTRES_ATTACK`, `ACTRES_BOMBARD`, `ACTRES_CAPTURE_UNITS`, `ACTRES_WIPE_UNITS`, `ACTRES_SPY_ATTACK`, `ACTRES_SPY_BRIBE_UNIT`, `ACTRES_CONQUER_CITY`, `ACTRES_DESTROY_CITY`, `ACTRES_SPY_INCITE_CITY`, `ACTRES_SPY_POISON`, `ACTRES_SPY_SPREAD_PLAGUE`, `ACTRES_SPY_SABOTAGE_CITY`, `ACTRES_SPY_TARGETED_SABOTAGE_CITY`, `ACTRES_SPY_SABOTAGE_CITY_PRODUCTION`, `ACTRES_SPY_SABOTAGE_UNIT`, `ACTRES_SPY_NUKE`, `ACTRES_NUKE`, `ACTRES_NUKE_UNITS`, `ACTRES_STRIKE_BUILDING`, `ACTRES_STRIKE_PRODUCTION`). Объявление войны нападением не считается: это новость, а не коллапс.

Запись ставится паре «нападавший, жертва» на `game.info.turn + 20`. Защитник в этой записи не помечается никогда: он жертва, а не источник.

Солидарность реализована не прямым чтением пары «напал на меня», а производной матрицей `dof_known_source[я][нападавший]`, которую пересобирает `dof_known_source_refresh()` раз в ход: нападавший считается источником, если у него есть живой флаг против **любой** жертвы, которую я знаю, и я знаком с самим нападавшим. Незнакомый нападавший не судится вовсе: незнание не приговор, а отсутствие оснований.

Производная сбрасывается при изменении знания внутри хода (новая запись в журнале источников обнуляет кэш), поэтому ответ не откладывается до следующего хода. Стоимость: один проход по тройке «нападавший, я, жертва» за ход, при восьми местах это 512 проверок; в плотных циклах военного планирования читается только кэш.

### §3.5. Журнал событий

Всё идёт через `dof_log()`, который пишет `log_normal("[DOF] ...")` и дублирует строку в `stderr`. Дубль появился по необходимости: на стенде publite2 запускает движки с `--log ../logs/...`, но файл журнала в этом окружении не обновляется, а `stderr` всегда попадает в `/docker/logs/freeciv-web-stderr-<port>.log`. Без дубля поведение DOF на живом стенде просто не видно.

### §3.6. Консоль

`dof_player_console()` разбирает `/aicmd <player> dof on|off|status`. Принуждение консоли (`force[idx]`) имеет приоритет над режимом файла, поэтому одно место можно переключить в живом мультиплеере, не трогая остальные.

### §4.4. `ai/default/daidiplomacy.c` (девять вставок)

Классический ИИ объявляет войну не из одного места, а из нескольких независимых путей. Гасить только один бессмысленно: остальные продолжают работать. Поэтому гейты стоят на всех путях.

**а) `dai_war_desire()` (строка ~831), начало расчёта:**

```c
  if (dof_enabled(pplayer) && !WAR(pplayer, target)
      && !dof_is_source(pplayer, target)) {
    dof_count_suppressed(pplayer, target);
    return 0;
  }
```

Это главный гейт: желание воевать с тем, с кем ещё не воюешь и кто не нападал, равно нулю. Здесь же считается метрика «сколько раз правило укусило»: первое подавление пары пишется в журнал строкой `desire_suppressed`, дальше растёт счётчик.

**б) `dai_diplomacy_first_contact()` (строка ~1002):**

```c
  dof_journal_contact(pplayer, aplayer);
```

Первый контакт пишется в журнал со статусом `MET` или `SOURCE`. Рандомизация «любви» ниже не тронута: она общая для обеих рук.

**в) `dai_go_to_war()` (строка ~1353), предохранитель:**

```c
  if (dof_enabled(pplayer) && !dof_is_source(pplayer, target)) {
    dof_journal_blocked(pplayer, target, "declare_war");
    adip->countdown = -1;
    return;
  }
```

Последняя линия обороны: какой бы путь ни привёл сюда, DOF-место не открывает войну против не-источника. Счётчик `countdown = -1` сбрасывает запланированную войну, иначе ИИ повторял бы попытку каждый ход.

**г) после подготовки объявления (строка ~1446):**

```c
  dof_journal_declare(pplayer, target, (int) reason);
```

Пишутся обе руки с флагом объявившего. Это и есть инструмент сравнения рук внутри одной партии.

**д) блок «остановить космогонку войной» (строка ~1658):**

```c
      if (dof_enabled(pplayer) && !dof_is_source(pplayer, aplayer)) {
        continue;
      }
```

Космическая победа это не нападение: война ради неё остаётся неспровоцированной атакой и для DOF-места запрещена.

**е) блок «нет целей», он же «война за добычей» (строка ~1711):**

```c
    if (dof_enabled(pplayer) && !dof_is_source(pplayer, aplayer)) {
      continue;
    }
```

Штатная логика классики звучит как «мы без целей, значит найдём жертву среди тех, кого давно знаем». Именно это поведение политика убирает: отсутствие врага не повод его назначить.

**ж) новый блок «война ответа» (строка ~1755, после `war_countdown` основного пути):**

```c
  if (dof_enabled(pplayer)) {
    players_iterate_alive(aplayer) {
      struct ai_dip_intel *adip = dai_diplomacy_get(ait, pplayer, aplayer);
      if (aplayer == pplayer || adip->countdown >= 0 || WAR(pplayer, aplayer)
          || NEVER_MET(pplayer, aplayer)) {
        continue;
      }
      if (dof_is_source(pplayer, aplayer)) {
        dof_journal_rule(pplayer, aplayer,
                         dof_source_is_third_party(pplayer, aplayer)
                         ? "war_on_source_third" : "war_on_source");
        war_countdown(ait, pplayer, aplayer, 2 + map_size_checked(),
                      DAI_WR_BEHAVIOUR);
      }
    } players_iterate_alive_end;
  }
```

Ответ на нападение не проходит через расчёт выгоды и через неприязнь: источник получает войну по факту. Задержка `2 + размер карты` взята короче классической (`4 + размер карты`), потому что это ответ, а не подготовка нападения.

**з) «война за союзника» (строка ~1785):**

```c
        && (!dof_enabled(pplayer) || dof_is_source(pplayer, aplayer))
```

Вступить в чужую войну это тоже открыть войну. Для DOF-места допустимо только против источника.

**и) «no mercy» (строка ~1851):**

```c
          || (aplayer == target && !dof_enabled(pplayer))
```

Штатная строка `aplayer == target /* no mercy */` не даёт предлагать мир главной цели войны, из-за чего война тянется до уничтожения. Для DOF-места она снимается: мир предлагается всем, включая текущую цель.

**к) `dai_diplomacy_actions()`, ветка `DS_WAR` (строка ~1991):**

```c
        if (dof_enabled(pplayer) && !dof_is_source(pplayer, aplayer)) {
          dof_journal_rule(pplayer, aplayer, "ceasefire_offer");
          clear_old_treaty(pplayer, aplayer);
          dai_diplomacy_suggest(pplayer, aplayer, CLAUSE_CEASEFIRE, FALSE, 0);
          adip->asked_about_ceasefire = is_human(aplayer) ? 9 : 0;
          dai_diplo_notify(aplayer,
                           _("*%s (AI)* We have no quarrel left with you. "
                             "Let the killing stop."),
                           player_name(pplayer));
          break;
        }
```

Перемирие не покупается: ветка `dai_goldequiv_clause(...) < 0` (цена мира в золоте и неприязни) для DOF-места обходится. Флаг источника истёк, значит предмета у войны нет.

### §4.5. `ai/default/daiactions.c`, `dai_action_value_unit_vs_city()` (строка ~98)

```c
  if (dof_enabled(actor_player)
      && !dof_is_source(actor_player, target_player)

      && !action_has_result(paction, ACTRES_ESTABLISH_EMBASSY)) {
```

Подкуп города (7000), саботаж (6000), кража технологии (9000), яд (2000) и ядерный удар шпионом (6500) это нападение под другим именем. Вне собственной войны и против не-источника их полезность обнуляется. Посольства исключены намеренно: это мирное присутствие, а не принуждение.

### §4.6. `ai/default/daiunit.h`, макрос `POTENTIALLY_HOSTILE_PLAYER`

```c
#define POTENTIALLY_HOSTILE_PLAYER(ait, pplayer, aplayer)               \
  (dof_enabled(pplayer)                                                 \
   ? (WAR(pplayer, aplayer) || dof_is_source(pplayer, aplayer))         \
   : (WAR(pplayer, aplayer) || NEVER_MET(pplayer, aplayer)              \
      || dai_diplomacy_get(ait, pplayer, aplayer)->countdown >= 0))
```

Штатное правило считает потенциально враждебным любого незнакомца. Для DOF-места незнакомец не цель: враждебность означает идущую войну или наблюдённое нападение. Макрос используется в плотных циклах военного планирования, поэтому цена проверки важна: `dof_enabled` кэширует чтение файла по номеру хода.

### §4.7. `server/srv_main.c`, `check_for_full_turn_done()` (строка ~2303)

```c
  if (!connected) {
    bool any_human = FALSE;
    players_iterate_alive(pplayer) {
      if (is_human(pplayer)) { any_human = TRUE; break; }
    } players_iterate_alive_end;
    if (any_human) {
      return;
    }
  }
```

Это не правило DOF, а требование замера. Безлюдная игра (`--type autogame`, клиента нет вообще) упиралась в ранний `return` и стояла на первом ходу: ход не завершался, потому что ждал клиента, которого не будет. Игры с живым игроком сохраняют штатное поведение.

### §4.8. `ai/default/daisettler.c` (две вставки, не DOF)

```c
-    log_normal("-------------best_impr---------- %f:%f", result->result, best_impr)
+    log_normal("-------------best_impr---------- %f:%f",
+               result != NULL ? result->result : 0.0, best_impr)
```

Отладочная печать веб-форка разыменовывала `NULL` (`find_best_city_placement()` законно возвращает `NULL`, когда земля кончилась). Любая длинная партия падала в segfault около 50-го хода, и в контроле тоже. Правка не относится к политике, но без неё замер невозможен.

## §5. Почему гейтов девять, а не один

Путь к войне у классического ИИ не единый: желание войны считается в `dai_war_desire()`, но объявление приходит ещё из четырёх независимых блоков `dai_diplomacy_actions()` (нет целей, космогонка, союзник, основная цель), а исполняется через `dai_go_to_war()`. Плюс два побочных пути принуждения: шпионские действия в `daiactions.c` и «потенциально враждебный» игрок в военном планировании. Если закрыть только желание, объявления продолжатся из блоков, которые считают повод сами.

Отсюда порядок уровней: желание (мягкий, основной), отдельные блоки (средний, по типу повода), предохранитель в `dai_go_to_war()` (жёсткий, ловит всё, что просочилось). Замер показал, что до жёсткого уровня не доходит ни разу: `blocked` в сериях равен нулю, всё гасится раньше. Это ожидаемо и одновременно метрика запаса прочности.

## §6. Границы изменения

Не изменено:

* человеческие места: код ИИ для них не исполняется вовсе;
* варвары: остаются целью, как в классике;
* экономика, наука, поселения, строительство, производство: правка не касается расчётов города и юнита;
* «любовь» и неприязнь: рандомизация и накопление отношений работают как раньше, DOF только не даёт им превратиться в объявление войны без повода;
* шпионаж и удары в **собственной** войне против источника: разрешены полностью;
* классическая рука: при `dof_enabled() == FALSE` каждая вставка сводится к исходному поведению, включая `POTENTIALLY_HOSTILE_PLAYER` и `no mercy`.

## §7. Переключатель и развёртывание

Файл `/docker/freeciv/dof_policy.conf`, одна строка, `#` начинает комментарий. Переопределяется переменной окружения `DOF_POLICY_FILE` (так серии разводят руки по разным файлам).

| значение | смысл |
|---|---|
| `none` | все места классические (контроль) |
| `all` | все ИИ-места по DOF |
| `even` / `odd` | DOF по чётности индекса игрока: обе руки в одной партии |
| `0,2,4` | явный список индексов мест |

Приоритет: консольное принуждение (`/aicmd <player> dof on|off`), затем режим файла. Файл читается в начале хода каждого ИИ-места, переключение горячее. Веб-интерфейс игры переключателя не имеет: в нём задаётся только число ИИ и уровень, DOF включается файлом, переменной или консолью.

Развёртывание: `sh deploy/freeciv-dof/apply.sh` кладёт `src/` и `work/` в контейнер, собирает `ninja freeciv-web` и ставит бинарь через `mv` (живущие движки держат старый inode, нужен `docker restart freeciv-web`). В образе то же самое делает `AI/freeciv-web/freeciv/patches/dof-principle.patch` и `Dockerfile.dof`.

## §8. Журнал: формат и инварианты

```
[DOF] policy=<spec> turn=N
[DOF] roster ai_seats=[Имя:idx=0:dof=1,...]
[DOF] contact turn=N me=X other=Y status=MET|SOURCE
[DOF] declare turn=N declarer=X target=Y declarer_dof=0|1 reason=N
[DOF] attack turn=N violator=X victim=Y violator_dof=0|1 victim_dof=0|1
[DOF] news turn=N violator=X victim=Y violator_dof=0|1
[DOF] event turn=N act=<rule> violator=X victim=Y mark=SOURCE|NEWS me=Z status=...
[DOF] rule turn=N me=X other=Y what=war_on_source|war_on_source_third|ceasefire_offer|coercion_refused
[DOF] desire_suppressed turn=N me=X other=Y n=1
[DOF] blocked turn=N me=X other=Y what=declare_war
[DOF] console me=X arg=on|off|status enabled=yes|no policy=<spec>
```

Инварианты: `declare`, `attack`, `news` пишутся для обеих рук; `roster` печатается при каждой смене политики и в начале партии, иначе строку журнала нельзя приписать руке; `desire_suppressed` пишется один раз на пару, чтобы разбор не тонул в повторах. Читать на стенде надо из `stderr` (`/docker/logs/freeciv-web-stderr-<port>.log`) при `--debug 2`: при `--debug 1` `log_normal` подавлен.

## §9. Замеры

Три уровня проверки, снизу вверх: A/B на четырёх партиях после M0+M1, серия из 12 партий по две руки после M2+M3, затем серии по трём рукам на 200 и 250 ходов. Вердикты предрегистрированы в плане (`drafts/DOF_CONTACT_PLAN.md`, §8) до данных: войн, начатых DOF-местами без повода, ноль при ненулевом числе у классических мест; отказов от принуждения против не-источников ноль; сила DOF-мест не ниже классических.

| рука | мест | объявлений | без повода | атак |

Средние на место (200 ходов, size 3): классика 172.1 score, 40.8 технологии, 144 bulbs/ход; DOF 181.7, 47.2, 395; смешанная партия в целом 170.0, 39.8, 134, при этом DOF-места 176.6, 40.8, 177 против классических мест тех же партий 163.4, 38.7, 92. На плотной карте (250 ходов): классика 169.3, 42.7, 150; DOF 213.7, 67.5, 1074; DOF-места смешанных партий 196.4, 47.8, 340 против классических 146.1, 39.8, 112.

Наоборот, DOF-места обгоняют классические и по score, и по науке, а в смешанных партиях классические места проседают сильнее, чем в чистых: их экономику сносит война, которую они сами и начинают. | рука | мест | объявлений | из них без повода | score | города | население | технологии | bulbs/ход |
|---|---|---|---|---|---|---|---|---|
| DOF-места (`mixed_sol`) | 24 | 12 | **0** | 175.8 | 19.8 | 63.5 | 40.8 | 155.9 |
| классические места тех же партий | 24 | 49 | 41 (84%) | 157.5 | 17.5 | 51.7 | 38.0 | 97.5 |
| контроль `classic_sol` | 48 | 138 | 130 (94%) | 172.1 | 18.4 | 58.5 | 40.8 | 144.2 |

Счётчики за серию: `war_on_source_third` 12, `ceasefire_offer` 740, `coercion_refused` 248, `blocked` 1. Все шесть партий дошли до конца, уничтоженных игроков ноль, падений нет.

Два вывода, которые держатся на числах. Первый: солидарность действительно включается, все 12 DOF-объявлений пришлись на того, кто до этого напал, и все 12 сопровождались строкой `war_on_source_third`, то есть это войны за третьих лиц, а не самозащита. Второй: контрольная ветка не сдвинулась ни на единицу, `classic_sol` повторила прежнюю классическую серию точно (138 объявлений, 238.2 убитых юнитов, score 172.1, 40.8 технологии, 144.2 bulbs), значит правка солидарности не задела классические места.

Цена солидарности видна в сравнении с серией без неё: DOF-места потеряли около 12% науки (177 → 156 bulbs) при том же score (176.6 → 175.8), а классические места в смешанных партиях просели сильнее (163.4 → 157.5), потому что теперь встречают коалицию. Число войн у DOF-мест выросло с 3 за 48 мест-партий до 12 за 24: правило начало работать не только в самозащите.

## §10. Ограничения и расхождения, которые надо знать

* **Нет отдельного `aitype dof`.** Политика это флаг на место внутри классического модуля. Для мультиплеера удобнее было бы отдельное имя ИИ, сейчас его нет.
* **Нет меры свободы.** Движок реализует запреты и обязательства, а не оценку `Σ ln(1 + опции)`. Утверждать по этим замерам, что DOF-место «максимизирует свободу», нельзя: проверено только, что оно не начинает войн и не принуждает.
* **Солидарность реализована, но в узком окне и без «защиты как таковой».** Источник распознаётся по нападению на любого, с кем место знакомо (§3.4), но ответ один: война против источника. Отдельного механизма «встать между нападающим и жертвой» (перехват, пересылка войск союзнику, ультиматум) нет, и жертва не получает от этого ни ресурсов, ни защиты. Флаг живёт 20 ходов, после чего война теряет предмет и предлагается мир, так продолжающийся конфликт будет признан заново только новым нападением.
* **Солидарность стоит войны.** Место, знающее и агрессора, и жертву, теперь вступает в конфликт, который его самого не касался. На короткой партии это увеличивает число войн и потерь у DOF-мест (см. §9, серия со солидарностью), и это цена доктрины, а не побочный эффект реализации.
* **Нет партий с живыми людьми.** Все серии безлюдные, все места встроенный ИИ. Поведение против человека проверено только по коду и на коротком клиентском прогоне.
* **Карты size 4 и 5, партии длиннее 250 ходов не покрыты.** Там классические войны начинаются позже, и вопрос «сколько объявлений предотвращает политика» остаётся открытым.
* **Дипломатический вес не моделируется.** DOF-место не оценивает, насколько предложенный мир увеличивает свободу партнёра; оно просто не мешает ему жить.
* **Журнал на стенде требует `--debug 2`.** При штатном `--debug 1` строки `[DOF]` не видны, а файл `--log` в этом окружении не обновляется вовсе, поэтому дубль в `stderr` обязателен.

## §11. Как воспроизвести

1. Сборка: `sh deploy/freeciv-dof/apply.sh`, затем `docker restart freeciv-web`. Инкрементальная пересборка одного файла около секунды.
2. Политика: `all`, `even`, `odd`, `none` или список индексов в `/docker/freeciv/dof_policy.conf`.
3. Безлюдный A/B: `.venv/bin/python deploy/freeciv-dof/run_ab.py --games 4 --turns 120 --aifill 8 --size 3 --par 4`.
4. Серия по одной руке: `.venv/bin/python deploy/freeciv-dof/run_series.py --tag dof --games 6 --turns 200 --aifill 8 --size 3 --par 2 --policy all`, сводка `series_report.py --tags classic,dof,mixed`.
5. Образ: `docker build -f Dockerfile.dof -t civrealm/freeciv-web:<tag> .` в `AI/freeciv-web`; патч уже в `freeciv/patches/` и в списке `apply_patches.sh`.
